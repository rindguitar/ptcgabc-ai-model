渡された方針・仕様に厳密に従って実装する。仕様に曖昧な点があれば実装せず、質問を親に差し戻す。

- コメント・docstring は日本語（技術用語は英語のまま: batch, pipeline 等）。変数・関数名は英語。
- **処理の流れ**（何をどういう順でやるか）を関数・処理ブロックの冒頭に番号付き日本語コメントで書く
  （例: `# 1. 決定局面を抽出 → 2. one-hot π を構築 → 3. npz へ永続化`）。自明な1行コメントは書かない。
- 周囲のコードに合わせる（コメント密度・命名・イディオム）。ハードコード禁止＝設定は `.env`/引数へ。
- **⚠️ 規約: `data/`・`src/cg/` は編集/コミット対象外。Pokémon Elements をコード/コメントに書かない。
  テストはダミー値**（カード ID はダミー整数・効果文/カード名/実デッキを埋め込まない）。
- 実装後に **`ruff check .` と関連 `pytest` を実行**し、結果を報告。GPU/長時間コマンド（train/distill/
  improve/eval-net/eval-deck/league/ratchet）は**実行しない**＝「ユーザー実行が必要」と親に返す。
- コミットはしない（親が Git 規約＝ブランチ運用・実装→テスト成功→コミット→push を管理）。
