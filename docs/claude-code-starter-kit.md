# Claude Code スターターキット（ptcgabc 適用版）

CLAUDE.md 本体とセットで使う付属ファイル群とプロンプト集（人間向けの説明書）。
このキットは3層でコンテキストを管理する:
- **常時ロード**: `CLAUDE.md`（薄く保つ。毎セッション・トークンを消費するため）
- **条件付きロード**: `.claude/rules/*.md`（paths 指定。該当ファイルを触るときだけロード・実挙動は要確認）
- **状態**: `docs/STATUS.md`（変化する情報。規約とは分離して化石化を防ぐ）

> このプロジェクトには既に `docs/learning/`（decisions.md §1〜・glossary・architecture・
> replay-format）と Claude の横断メモリがある。キットはそれと**競合させない**:
> 設計判断（ADR）は `docs/learning/decisions.md` が正（2026-07-19 に design-decisions.md から改名）。

## 2. サブエージェントについて（このプランでは慎重に）

テンプレ本来の狙いは「探索/テストを安価なモデルへ逃がす」だが、**このプランでは spawn ごとに
コンテキストを冷えた状態から再構築＝高コスト**になりうる。原則 inline で処理し、
**独立・並列化できる大きな一括処理**（例: 多数 replay の一括分類・広範な grep 走査）を
親のコンテキストを汚さず回したい時だけ委譲する。導入後 `/cost` で実挙動を確認。

## 3. セッションプロンプト集（PTCG 版）

### 3-1. 再開（最頻出）
```
docs/STATUS.md を読んで「次の一手」の1番から進めてください。着手前に今日のゴールを1〜3行で確認。
```

### 3-2. 新フェーズの開始
```
新フェーズ: 「（例）クローン継ぎ足しラウンド2」
まず実装せず、①方針（選択肢が複数なら比較して推奨）②影響/新規ファイル一覧
③3〜5ステップの計画 を提示してください。承認したらステップ1のみ着手。
```

### 3-3. 設計レビュー
```
（対象ファイル/設計）をレビュー。観点: ①欠陥・見落としエッジケース ②拡張性 ③過剰設計。
コードの書き直しは不要、指摘と理由のみ重要度順に。
```

### 3-4. デバッグ
```
（症状。エラーは要点のみ）まず原因仮説を確度順に2〜3個＋各検証方法を提示。
原因が確定するまで修正コードは書かないでください。
```

### 3-5. 終了（毎回）
```
ここまでにします。docs/STATUS.md を更新（前回やったこと/次の一手/未解決）。
設計判断があれば docs/learning/decisions.md に「## N.」で追記・新語は glossary へ。
コミット・プッシュ漏れがないかも確認してください。
```

### 3-6. コンテキストが重くなってきたとき
```
ここまでの作業内容と決定事項を docs/STATUS.md に反映してください。反映後、新しいセッションで続きます。
```

## 4. 運用のコツ（人間側）

- **1セッション1目的**。跨ぐなら STATUS を更新して新セッションへ（長いコンテキストは高い）。
- 計画立案には **Plan モード**（Shift+Tab）＝実装前の思考に編集権限は不要。
- STATUS が肥大したら古い内容を decisions.md へ移し「現在地」だけに保つ。
- 規約が増えたら CLAUDE.md に足さず `.claude/rules/` にトピック別で。
- Claude に同じ指摘を2回したら、その場で `#` から始めて即追記する。
- このキット自体もプロジェクトに合わせて削る・足す（このファイルが適用版）。

## 5. このリポジトリ特有の注意（落とし穴）

- **競技規約が最優先**: `data/`・`src/cg/` 非公開、Pokémon Elements をどこにも貼らない（テストもダミー値）。
  CLAUDE.md の ⚠️ 規約節を絶対に落とさない。
- **Git 規約**: main 直接コミット禁止・`feature/<内容>`/`fix/<内容>` を切って開始前に push
  （例外: STATUS.md 更新のみ現在ブランチ可）。
- **長時間・GPU コマンドはユーザーが実行**（train/distill/eval-net/eval-deck/league/ratchet 等）。
- **replay JSON は teacher-extract / replay-extract を済ませるまで削除しない**（行動クローンは生 JSON が必要）。
- 判定の作法: keep-best・外部 A/B・事前登録（decisions.md §21/§30/§34）。
